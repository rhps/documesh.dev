Documesh MCP Server — WebMCP Tool Reference

Documesh is an application powered by WebMCP. These are the exact tools this website registers via document.modelContext.registerTool() — the contract any compatible agent discovers and operates when you open this site in ChatGPT's in-app browser or Chrome with WebMCP enabled.

What is WebMCP?

WebMCP is an emerging open standard (W3C Web Machine Learning community group, developed with Microsoft and Google) that lets a website declare structured tools for AI agents. Instead of an agent scraping HTML and guessing, the page hands over a machine-readable tool list: names, descriptions, JSON Schemas. The agent reads the contract and calls tools directly — while the visual UI stays on screen for the human. Think of it as the difference between reading a building's floor plan and wandering the halls hoping to find the right room.

Connect an agent

ChatGPT (in-app browser)

Open documesh.dev in ChatGPT's in-app browser and ask naturally: "search the docs for edge function environment variables." WebMCP is supported out of the box — the agent finds and calls the tools.

Google Chrome 149+

Enable chrome://flags/#enable-webmcp-testing, restart, then open the site and converse with your WebMCP-compatible agent of choice.

Design principles

  • 1.Risk-typed tools. Every tool declares its class — answer (read-only), act (writes, always queued proposals). Six tools are read-only; the two act tools never mutate the corpus directly — submissions and reports are append-only proposals, reviewed before sync.
  • 2.Provenance mandatory. Responses without license, source_url and last_updated fail at the schema level — attribution is structural, not optional.
  • 3.Honest abstention. explain_error labels low-confidence results as "closest matches" and never presents a guess as the answer.
  • 4.One tool per intent. No near-duplicate tool spam — models lose accuracy on bloated tool lists, so the mesh keeps a minimal canonical surface.

Tools

answer read-only · safe

search_docs_across

Search federated developer documentation across all mesh sources. Returns ranked excerpts with version, license, and canonical source URL for every result.

Request
{
  "query": "edge functions environment variables",
  "sources": ["netlify", "vercel"],   // optional filter
  "limit": 5                          // optional, default 5
}
Response
{
  "snapshot_date": "2026-08-30",
  "results": [{
    "source": "netlify", "version": "latest",
    "title": "Environment variables at Netlify",
    "section": "Build > Environment variables > Overview",
    "excerpt_link": "https://docs.netlify.com/build/env/overview/",
    "license": "Netlify Docs (agent-permitted via llms.txt)",
    "last_updated": "2026-08-30", "relevance": 274.66
  }]
}
Sources: cloudflare · netlify · vercel · kubernetes · bun · elysia · turso · upstash · sentry · stripe · hono · nuxt · solid · opentelemetry · argocd
answer read-only · honest abstention built in

explain_error

Given a log excerpt or error message, find the closest matching documentation sections across mesh sources. Extracts error signatures (exception names, k8s reasons, errno codes, exit codes) and returns version-cited sections with an explicit disclaimer.

Request
{
  "log_excerpt": "Back-off restarting failed container. Error: CrashLoopBackOff",
  "source": "kubernetes"   // optional filter
}
Response
{
  "extracted_signatures": ["CrashLoopBackOff", "Error: CrashLoopBackOff…"],
  "matches": [{
    "source": "kubernetes",
    "title": "How Pods handle problems with containers",
    "source_url": "https://kubernetes.io/docs/concepts/workloads/pods/pod-lifecycle/",
    "license": "CC-BY-4.0", "score": 252.4
  }],
  "disclaimer": "These are the closest documentation sections, not a diagnosis…"
}
Eval: 5/5 curated real-world errors matched the correct section in top-3 (100%).

verify_config

Diff a user's configuration file against the keys a source actually documents. Returns missing_keys (documented but absent from the config — each cited to the exact doc page) and unknown_keys (present in the config but never documented — possible typos). Chain after search_docs_across when the user asks "is my config right?".

Request
{
  "source": "cloudflare",
  "config_text": "name = my-worker\ncompatibility_date = \"2024-09-23\"\n\n[vars]\nAPI_KEY = \"xyz\"",
  "config_query": "wrangler configuration"   // optional — which docs to compare against
}
Response (abridged)
{
  "missing_keys": [{ "key": "triggers.crons",
    "documented_in": { "title": "Cron Triggers", "source_url": "https://developers.cloudflare.com/…" } }],
  "unknown_keys": ["name", "main"],
  "disclaimer": "Heuristic diff — missing ≠ wrong; only documented keys are checked…"
}
answer read-only · cross-source mapping

compare_configs

"I know Netlify's redirect syntax — what's the Vercel equivalent?" Maps documented config keys between two sources: matched keys (by name or concept overlap) come back with citations on both sides; unmatched keys are listed explicitly as gaps. Heuristic, honest about limits — "no equivalent found" means none documented under a matching name.

Request
{
  "source_a": "netlify",
  "source_b": "vercel",
  "query_a": "netlify redirects configuration",   // optional
  "query_b": "vercel redirects configuration"    // optional
}
Response (abridged)
{
  "common":     [{ "key_a": "redirects", "key_b": "redirects", "match": "exact", /* + both citations */ }],
  "only_a":    [{ "key": "build.command", /* + citation */ }],
  "only_b":    [{ "key": "headers", /* + citation */ }],
  "disclaimer": "Key mapping is heuristic (name + concept overlap), not semantic proof…"
}
answer read-only · live status probe

check_service_health

Probe a provider's public status page — cloudflare, github, npm, or sentry. Chain after explain_error to answer the follow-up every developer has: "is the service down, or is it my code?" Read-only, no auth.

Request
{ "provider": "cloudflare" }
Response
{
  "provider": "cloudflare", "name": "Cloudflare",
  "indicator": "minor", "description": "Minor Service Outage",
  "checked_at": "2026-09-03T17:09:04Z",
  "status_url": "https://www.cloudflarestatus.com/…"
}
act queued proposal · never mutates the mesh directly

report_issue

Report a documentation problem — outdated, incorrect, misattributed, license-mismatch, or broken-link — against a specific chunk from a search result. Reports are appended to a triage queue and reviewed before the next sync cycle. The corpus itself is never mutated by a report.

Request
{
  "source_id": "cloudflare",
  "chunk_id": "cf-workers-cron-007",      // from a search result
  "issue_type": "outdated",                 // outdated | incorrect | misattributed | license-mismatch | broken-link
  "detail": "Screenshot shows the old dashboard UI",
  "suggested_fix": "…",                     // optional
  "reporter": "rio"                        // optional
}
Response
{ "issue_id": "5cf8e2cb-…", "status": "open",
  "poll": "/v1/issues/5cf8e2cb-…" }
act async job · 202 + polling

submit_source

Submit a documentation source for ingestion review. Requires a name and license; the docs origin is checked against our ingestion policy (official agent interface or permissively-licensed repo — we never scrape). Returns an async job you poll.

Request
{
  "name": "Example CLI",
  "license": "MIT",
  "docs_origin": "https://docs.example.com/llms.txt"   // optional
}
Response
{ "job_id": "b46aa7d4-…", "status": "processing",
  "poll": "/v1/jobs/b46aa7d4-…" }
answer read-only · no parameters

contribution_stats

Live mesh counters: source submissions in flight, open and total issue reports, sources indexed, and total chunks. Use it to gauge mesh health or to cite contribution activity.

Registration snippet

This is the actual pattern used on this site (simplified):

// app.html — registers Documesh capabilities with any visiting agent
const ctx = document.modelContext;

ctx.registerTool({
  name: "search_docs_across",
  description: "Search federated developer documentation…",
  inputSchema: {
    type: "object",
    properties: {
      query:   { type: "string", description: "Search query" },
      sources: { type: "array",  description: "Optional source filter" },
      limit:   { type: "number", description: "Max results" }
    },
    required: ["query"]
  },
  execute: async (input) => {
    const data = await fetch(`/search?q=${input.query}`).then(r => r.json());
    return data;  // license + source + version on every result
  }
});

Response contract

Every tool response satisfies these invariants — enforced by the indexer and API, verifiable by any agent:

✅ license present on every result
✅ source_url → canonical source page
✅ last_updated dated snapshot
✅ excerpts only — never full-text mirroring
✅ deterministic scoring (same query → same order)
✅ explicit disclaimers on probabilistic matches
